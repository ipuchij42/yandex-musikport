# YMP — мини-клиент Яндекс Музыки для HP iPAQ 214 (Windows Mobile 6)

Один файл исходников (`ymp.c`, ~600 строк), TLS 1.2 через mbedTLS, декодер minimp3, вывод через waveOut.
Ожидаемый размер exe: ~600–900 КБ. Ограничение в 20 МБ не проблема.

## Что понадобится

1. **cegcc** — GCC-кросс-компилятор под Windows CE ARM (`arm-mingw32ce-gcc`).
   Собирается на Linux или в Cygwin. Берём его вместо Visual Studio 2008, потому что
   VS2008 не умеет C99 (нет `stdint.h`), а mbedTLS и minimp3 на нём не соберутся.
2. **mbedTLS 2.28 LTS** (именно 2.x, у 3.x другой API): https://github.com/Mbed-TLS/mbedtls
   Распакуйте в `mbedtls-2.28/`.
3. **minimp3.h**: https://github.com/lieff/minimp3 — положите рядом с `ymp.c`.

## Сборка

```sh
chmod +x build.sh
./build.sh > build.log 2>&1
echo "код: $?"
```

Код `0` значит, что сборка прошла и рядом появился `ymp.exe`; иначе смотрите `build.log`.
Если собираете в Ubuntu под WSL, готовый файл можно скопировать в папку Windows (подставьте своё имя пользователя):

```sh
cp ymp.exe /mnt/c/Users/ИМЯ_ПОЛЬЗОВАТЕЛЯ/Downloads/
```

Получится `ymp.exe`. Скопируйте на КПК в одну папку вместе с `ymp.ini` (скопируйте `ymp.ini.example` в `ymp.ini` и впишите свои данные)
(имя ini должно совпадать с именем exe).

## ymp.ini

| ключ | что это |
|---|---|
| `token` | OAuth-токен аккаунта с Яндекс Плюс. Получите на ПК любым способом из документации библиотеки `yandex-music` (MarshalX) |
| `hmac` | ключ подписи запросов `get-file-info`. Это общий (не личный) ключ из веб-плеера Яндекса, он не привязан к вашему аккаунту. Значение по умолчанию лежит в `ymp.ini.example`. Ключ меняется при выходе нового фронтенда - актуальный ищите в проекте `yt-dlp-yandex-music` (параметр `hmac_key`) |
| `host` | API-хост, по умолчанию `api.music.yandex.net` |
| `quality` | `lq` или `nq` (MP3 экономнее по трафику и CPU) |
| `count` | сколько лайкнутых треков загружать (до 100) |

## Как это работает

1. `GET /account/status` → uid
2. `GET /users/{uid}/likes/tracks` → id треков, затем `POST /tracks` → названия
3. `GET /get-file-info?ts&trackId&quality&codecs=mp3&transports=encraw&sign`
   - `sign = base64(HMAC-SHA256(hmac, ts+trackId+quality+codecs+transports))` без `=` в конце
   - в ответе `url` и `key` (hex)
4. Скачивание по `url`, расшифровка AES-CTR (нулевой 16-байтовый счётчик), minimp3 → waveOut

## Управление

Двойной тап по треку — играть. Кнопки внизу: предыдущий / пауза / следующий. Следующий трек стартует сам.

## Ограничения и честные оговорки

- **Код не проверялся на железе.** Писался без возможности собрать ARM-бинарник, ожидайте пару правок при первой компиляции.
- **Сертификат сервера не проверяется** (`MBEDTLS_SSL_VERIFY_NONE`), чтобы не таскать список корневых CA. Трафик шифрован, но защиты от подмены сервера (MITM) нет, а токен уходит в этом канале. Можно добавить проверку, вшив корневой сертификат Яндекса/GlobalSign.
- **Время на КПК должно быть верным** — `ts` в подписи берётся из системных часов.
- API неофициальный: ключ, эндпоинты и схема шифрования могут поменяться. Использование на свой риск, возможны претензии по условиям сервиса.
- Редиректы (302) на CDN не обрабатываются.
- Если звук рвётся: PXA270 без FPU, minimp3 считает во float программно. Тогда качество `lq`, либо замена декодера на libmad (целочисленный).
- Wi-Fi: iPAQ 214 нормально дружит с WPA2-AES; WPA3 не поддерживается.


## Что изменилось в версии 1.1

- **Поиск.** Исправлена ошибка «Ничего не найдено (HTTP 200)»: разбор ответа был ограничен размером очереди, и когда
  очередь «Моей волны» разрасталась до лимита, любой поиск казался пустым. Окно «Найдено N» убрано, результат виден в списке и в строке статуса.
- **Текст песни.** Три источника по очереди: подписанный запрос Яндекса → `/tracks/{id}/supplement` → lrclib.net (открытая база текстов).
  Если не нашлось нигде, в окне текста показаны коды ответов каждого источника, а подробности записаны в `ymp.log` рядом с exe.
- **Повторы песен.** Дубли внутри очереди отбрасываются; прослушанное запоминается в `ymp.hist` (последние 300 треков, переживает перезапуск);
  «Моя волна» получает обратную связь (`radioStarted`, `trackStarted`, `trackFinished`, `skip`); продолжение просит треки по id последнего трека очереди.
  Если сервер присылает только уже игранное, берутся повторы - музыка не прерывается.
  Размер очереди увеличен до 300.
- **Главное / Любимое.** «Главное» - просто главный экран. «Любимое» - отдельный слой со списком любимых: музыка продолжает играть,
  очередь не меняется. Очередь заменяется любимыми только когда вы дважды тапнули трек в этом списке. Кнопка «Моя волна» на главном экране,
  пока волна уже играет, просто возвращает к плееру, а не запускает её заново.
  Исправлено перекрытие зон касания: верх значков «Главное»/«Любимое» раньше попадал в полосу перемотки и сбивал позицию трека.
- **Возврат в приложение.** Запуск ymp.exe при уже запущенном приложении (его свернули крестиком) выводит на экран работающий экземпляр,
  а не запускает вторую параллельную музыку. При возврате в окно экран синхронизируется с тем, что играет сейчас (трек, обложка, выделение в списке).
